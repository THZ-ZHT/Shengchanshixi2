## 多模态图像合成 Agent · 自然语言指令实时换背景修复（同日追加）

### 问题

用户反馈：「只要一输入指令，它就立马变回示例的背景」。
根因：
- `orchestrator.ts` 的 `n6` 节点在每次合成结果时直接返回 `user.final`（上传时缓存的固定合成图），而不是按当前 `bgPreset` 重新合成。
- `commandParser.ts` 把 "把背景换成咖啡馆" 误判为 `custom_bg`（提示词被截成 "把"），因为 `custom_bg` 的 "换成"+"背景" 组合关键词检查在 preset 检测之前执行。

### 修复

1. **orchestrator.ts**
   - `produceArtifact` 改为 `async`；`n6` 节点调用新增 `renderCurrentComposite()` 按当前 `bgPreset` 实时 `composeUserPreview`。
   - 用户上传时：用 `user.subject` 合成到新背景；无用户时：用 `DEMO.subject` 合成到新背景。
   - `custom_bg` 不再直接塞背景图，而是触发 `n6` 重合成。
   - `runDag` / `regenerateNode` 全部 `await produceArtifact`。
2. **commandParser.ts**
   - 预设检测移到 `custom_bg` 之前；若检测到预设关键词（咖啡/湖/城市/森林等），直接走 `switch_bg`。
   - 删除原本末尾重复的 preset 检测。
3. **qa_run.cjs**
   - 新增 `BG_SWITCH` 自动校验：指令前后抓画布主图 dataURL 的 hash/长度，确认 `changed=true`。
   - 新增 `USER_BG_SWITCH` 校验：对上传图输入换背景指令，同样确认结果图改变。
   - 将 QA 访问地址从 5173 切到 4173 生产预览。

### 经验沉淀

- 缓存的 `user.final` 是动态合成场景的大敌：任何依赖 "最终合成图" 的状态机在指令/参数变化后都必须重新渲染，否则画布就是静态贴纸。
- 自然语言解析的顺序很重要：预设词优先于开放生成词，否则用户的确定性表达会被降级为模糊的 custom prompt。
- 自动化 QA 要做 "视觉级断言" 而不是只看流程跑通：dataURL hash/长度比对是离屏验证合成结果变化的轻量方法。

## 多模态图像合成 Agent · 主体 AI 立体化 + 背景回归 bug 修复（同日追加）

### 问题

用户追加两点需求：
1. 抠出来的主体放进背景太"贴纸"，希望 AI 立体化/延伸。
2. 选择其它背景图后点击「生成」会回到示例背景。

根因：
- `ImageGenPanel.tsx` 的 `generate()` / `handleUpload()` 里 `sourceUrl` 硬编码为 `/assets/demo/kf_subject.png`，导致无论用户上传什么主体，AI 生图面板都使用 demo 主体。
- `composeUserPreview` / `composeEngine` 之前只把主体平贴到背景上，没有体积/厚度处理。
- `ModelGenPanel` 的「图生 3D」本地高度场也用 `DEMO.subject`，没有利用用户真实抠图。

### 修复

1. **ImageGenPanel.tsx**
   - 新增 `getSubjectSource()`：优先 `compositionStore.userImage.subject`，其次工作台 `mask` 资产，最后回退 demo。
   - `generate()` 和 `handleUpload()` 的 `sourceUrl` 全部改为 `getSubjectSource()`。

2. **主体立体化（composePreview.ts）**
   - 新增 `drawSubjectWithRelief()`：在 offscreen canvas 里为主体叠加「厚度偏移暗边 + 顶部高光/底部暗部体积渐变 + 边缘轮廓」。
   - `composeUserPreview` 默认启用 `withRelief`。
   - 导出 `drawSubjectWithRelief` 供 `composeEngine.ts` 复用。

3. **composeEngine.ts**
   - import `drawSubjectWithRelief`；在最终合成阶段用它代替直接 `drawImage(subject)`，让 ImageGenPanel 生成的结果也带立体感。

4. **图生 3D（heightmap.ts + ModelGenPanel.tsx）**
   - `buildHeightmap` 改为 alpha 主导高度（主体整体凸起）+ luminance 细节 + 中心区域额外凸起（模拟躯干/头部雕塑感）。
   - `ModelGenPanel.LocalMeshViewer.generate()` 用 `getSubjectSource()` 读取用户主体，不再硬编码 `DEMO.subject`。
   - PlaneGeometry ratio 改为主体实际宽高比；高度缩放从 0.5 提到 0.7；材质开启 `transparent` + `alphaTest: 0.05` 裁掉透明背景。

### 经验沉淀

- 前端合成场景里的"主体"必须全局动态解析：任何 hard-code demo sourceUrl 的地方，在用户上传后都会变成回归示例的 bug。
- 减少"贴纸感"的低成本方案是"体积渐变 + 厚度边缘"，比真正的 AI 补全/延伸更可控，且纯浏览器实时可用；真正的"延伸"（补全被截断的肢体）仍需后端生成模型。
- 3D 高度场设计：alpha 决定"是否凸起"、亮度决定"表面起伏"、中心 bulge 决定"整体体积感"，三者结合比单一亮度高度场更像雕塑。
